# ARC-013 — Единый composition root и DI setup

- Статус: DONE (принято координатором 2026-09-05)
- Владелец: Claude
- Scope: `src/ui/composition-root.ts` (новый), `src/ui/App.tsx`, `eslint.config.js`. Не
  пересекается с файлами art-агента (`prototype-scene.ts`, `arena-decoration.ts`,
  `dream-environment-manifest.ts`).
- Изменённые файлы:
  - `src/ui/composition-root.ts` (новый) — `createAppServices()`, единая точка сборки
    app-lifetime singletons: `AppController`, `GameInputState`, `ProgressService` +
    `LocalStorageSaveRepository`.
  - `src/ui/App.tsx` — вместо трёх отдельных `useState(() => new X())` со сборкой адаптеров
    прямо в компоненте, теперь один `useState(createAppServices)`, деструктурируемый на
    `appController`/`inputState`/`progressService`. Прямые импорты `AppController`,
    `GameInputState`, `LocalStorageSaveRepository` в `App.tsx` убраны.
  - `eslint.config.js` — исключение из правила «запрет на `window.localStorage`» перенесено с
    `src/ui/App.tsx` на `src/ui/composition-root.ts` (композиция теперь происходит там).
- Что реализовано: `App.tsx` больше не знает о конкретных адаптерах (`LocalStorageSaveRepository`,
  `GameInputState`) — он получает уже собранные сервисы из `createAppServices()`. Единственное
  место, которое одновременно видит `@application` (порты/сервисы) и `@adapters` (конкретные
  реализации) — `src/ui/composition-root.ts`, что соответствует роли "composition root" в чистой
  архитектуре: точка, где абстракции связываются с конкретными реализациями, и ничего выше по
  дереву компонентов не должно об этом знать.
- Что намеренно не реализовано:
  - Полноценный DI-контейнер (реестр/токены/lazy resolution) не создавался — при текущем размере
    приложения (несколько app-lifetime синглтонов) простая фабричная функция `createAppServices()`
    прозрачнее и не требует новой инфраструктуры/зависимости. Контейнер имеет смысл только если
    число сервисов или сценариев их подмены (например для тестов) вырастет значительно.
  - `GameplayController` (создаётся отдельно, per-level, через `createCampaignGameplay()`) не
    перенесён в `composition-root.ts` — он не app-lifetime синглтон, а создаётся заново при каждом
    новом уровне/рестарте с разным `content`/`progress`, поэтому его конструирование логично
    остаётся рядом с местом использования в `App.tsx`, а не в композиционном корне
    app-уровневых сервисов.
  - Haptics (`WebHapticsAdapter`) не переносился в composition root — он создаётся внутри
    `PrototypeScene` (`src/adapters/phaser/prototype-scene.ts`), файла, который сейчас правит
    art-агент; трогать его вне scope этой задачи и текущей синхронизации.
- Изменённые контракты: нет изменений публичного API `@application`/`@adapters` — только то, кто
  их вызывает и откуда. `App.tsx` теперь получает `AppController`/`GameInputState`/
  `ProgressService` через `createAppServices()` вместо прямого конструирования — любой будущий
  код, тестирующий `App` в изоляции, может подменить `createAppServices` (например через
  `vi.mock('@ui/composition-root', ...)`) вместо мокания трёх отдельных адаптеров.
- Проверки и результаты:
  - `npm run lint` — чисто.
  - `npm run typecheck` — чисто.
  - `npm run test` — 14 файлов / 35 тестов, все проходят без изменений в тестах — существующие
    `tests/unit/app.test.tsx` рендерят `<App />` целиком и неявно проверяют, что
    `createAppServices()` корректно собирает рабочие сервисы (boot → main-menu → intro → уровень
    проходят как раньше).
  - `npm run build` — production build проходит.
  - `npm run format:check` — чисто для всех изменённых файлов.
- Ручная проверка: не требуется — существующий `tests/unit/app.test.tsx` уже покрывает полный
  жизненный цикл `App` (boot/main-menu/intro/старт уровня), что фактически является
  интеграционной проверкой composition root.
- Скриншоты/видео: не применимо (без визуальных изменений).
- Известные ограничения: `createAppServices()` — не мемоизированная фабрика в чистом виде, она

  повторном рендере `App` не пересоздаёт сервисы, поведение идентично исходному коду с тремя
  `useState`.
- Риски для следующих задач: нет — изменение полностью изолировано в `src/ui`, не затрагивает
  `core`/`application`/`adapters`/`content` публичные контракты.
