## GAM-001 — Camera perspective и размер котов

**Решение пользователя (2026-09-05):** утверждён текущий de-facto прототип как целевой для всех
7 уровней — не найдено требований в сценарии, которые бы противоречили этому выбору (сценарий
не фиксирует конкретную камеру/масштаб, только описывает пространство сцен через ориентиры,
"дальние планы" и "панорамные сцены", что совместимо с любым разумным platformer-масштабом).

- Камера: горизонтальный side-scroll, плавное слежение за активным котом (lerp 0.09/0.09,
  `PrototypeScene#create()`), deadzone 260×130px. Вертикального скролла нет — высота мира
  (720px) равна высоте viewport (`PLATFORMER_WORLD_HEIGHT`, `arena-decoration.ts`).
- Коты: спрайт-масштаб 0.58 от исходных ~280×275px кадров атласа → ~160×160px на экране
  1280×720, то есть кот занимает **~22% высоты экрана** — заметный, «arcade-platformer» масштаб.

Последствие для контента: раз вертикального скролла нет, **вертикальные** ориентиры уровней
(башня-обсерватория, маяк, Центральная башня, колесо обозрения, одинокое дерево) должны читаться
через горизонтальные "дальние планы"/параллакс, а не через камеру, поднимающуюся по уровню —
это ограничение для будущей геометрии/арта, а не для GAM-001 самого по себе.

## GAM-002 — Movement metrics и obstacle kit

### Movement metrics

**Решение пользователя (2026-09-05):** утверждены текущие de-facto метрики как целевые на все
7 уровней (без прогрессии скорости/прыжка по уровням — сложность растёт иначе, см. GAM-003):

- горизонтальная скорость: 255 px/с;
- прыжок: 560 px/с вверх, гравитация 1050 px/с² (высота прыжка ≈ рост кота);
- coyote time 120мс, jump buffer 130мс;
- анти-softlock: 1400мс без прогресса при зажатом направлении → авто-подскок.

### Obstacle kit — **не единый набор**, свой на каждый уровень

Первая версия этого раздела ошибочно описывала общий для всех уровней "kit" (платформы/
day-night-мосты/hazards/cover zones) — это неверно. Сценарий §12 «Уровни» и §12 «Общее правило
окружения всех уровней» прямо требуют: **у каждого уровня свой рельеф и минимум три тематических
взаимодействия с окружением**, и **запрещает** переиспользовать один набор платформ с новой
декорацией. Ниже — обязательный набор *уникальных* элементов рельefa/интерактива по каждому
уровню, выписанный дословно по смыслу сценария (не изобретено, см. первоисточник в скобках):

| Уровень | Уникальный рельеф (не переиспользуется на других уровнях)                                                                                       | Уникальные интерактивные элементы                                                                                                                    |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |

**Технические следствия для будущей задачи (не входит в GAM-002 саму по себе, это про
`campaign-levels.ts`):**

- Текущий graybox (`LV-GRAYBOX-7`) использует **общую** геометрию (статичные платформы,
  `phasePlatforms`, `hazards`, `coverZones`) без уникальных механик выше — это осознанный
  плейсхолдер для проходимости, не финальный контент (см. `docs/HANDOFFS/LV-GRAYBOX-7.md`).
  Подключение реальных уникальных механик каждого уровня (мушмороны-грибы, вагончики трамвая,
  складывание бумаги, колесо обозрения, воздушный змей и т.д.) — это content-задачи `LV1-NNN`
  .. `LV7-NNN` по плану, каждая описана отдельно, не одна большая задача.
- `PlatformerHazardSystem`/`PhaseBridgeSystem`/`GardenFlowerPuzzle` и т.д. уже реализуют
  паттерн "система на уникальную механику уровня" (см. `LevelMechanicsSystem`) — новые уровни
  должны получить свои системы по тому же паттерну (`docs/ADDING_CONTENT.md`), а не попытку
  впихнуть всё через один общий `mechanic` enum.

## GAM-005 — Enemy role matrix

| ------- | --------------------------------------- | -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |

| 2       | Собиратели огоньков (`light-collector`) | Маскообразные существа, гасят фонари, уносят свет в мешках; Крик заставляет выронить свет          | Погоня за самым большим Собирателем по ветвям во время смены фаз (не традиционный босс) |
| 3       | Спешуны (`hurry-up`)                    | Заводные будильники; толкают и включают механизмы раньше времени, не столько атакуют               | Смотритель Полудня — большой автомат, **оглушают и снимают перегрев**, не уничтожают    |
| 4       | Кляксы (`blot`) + Чернильный шторм      | Малые опасности среды, рассеиваются светом/криком; шторм — управление парусом, не бой с боссом     | Удержание линзы маяка во время шторма — испытание окружения, не файт                    |
| 5       | нет традиционных врагов                 | Маэстро Улыбка — не злодей, отвлекает новыми развлечениями                                         | Погоня по аттракционам + головоломка остановки карусели (non-lethal)                    |
| 6       | Бесконечный марш (`endless-march`)      | Пустые доспехи; не обязательно уничтожать — разбирают знамёна, меняют направление марша            | Без традиционного босса — защита Элиаса, пока он дослушивает послание Арена             |
| 7       | Страж Безмолвия (`guardian-of-silence`) | Оболочка сна из масок/дверей/спящих рук; цель — разбить **четыре замка**, не убить существо        | Часть 3-4: совместное спасение (Нить домой) → управляемый выбор Элиаса                  |

Ключевой паттерн по всей игре (сценарий §14 «Сложность и честность»): **ни один враг не
уничтожается как самоцель** — победа всегда выражается через оглушение/перенаправление/защиту, а
не разрушение. Финальные противники не вводят правил, которым игра не обучала раньше.

Текущая реализация (`docs/HANDOFFS/LV-GRAYBOX-7.md`) переиспользует **старых** врагов старого
канона (shadefang, thorn-stalker, clockwork-mite и т.д.) как graybox-плейсхолдеры для геометрии
всех 7 уровней — таблица выше описывает **целевых** врагов нового канона, для которых уже
доставлены спрайты (`src/assets/sprites/enemies/*`, см. `docs/ASSET_MANIFEST.md`), но нет ни
`EnemyConfig`, ни атласов, ни adapter-кода. Это отдельная задача (см. `docs/HANDOFFS/LV-GRAYBOX-7.md`
→ «Что намеренно не реализовано»).

## GAM-003 — Difficulty curve

Сценарий §14 «Сложность и честность» фиксирует главный принцип буквально: **«сложность
повышается комбинацией известных правил, а не ростом здоровья противников»**. Это значит, что
`EnemyConfig.health`/`contactDamage` не должны линейно расти от уровня к уровню — точные цифры
для нового канона врагов фиксировать пока рано (новые враги ещё не реализованы, см. GAM-005), но
сама **форма** кривой уже полностью задана сценарием per-level:

| Уровень | Боевая нагрузка (из сценария)                                                                          | Новый элемент, из которого растёт сложность                          |
| ------- | ------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 1       | Первый бой вообще — короткий, обучающий, урон снижен, чекпоинт прямо перед землетрясением, нельзя проиграть мгновенно | Введение боя как такового + смена активного бойца день/ночь            |
| 2       | Собиратели огоньков — не смертельны, воруют свет; финал — погоня, не файт                                | Комбинация Крика (уже знаком) + Игл (новая способность) против одной роли врага |
| 3       | Спешуны толкают/мешают, не столько атакуют; финал — оглушить автомат, не убить                           | Управление окружением (зеркала/синхронизация) во время помех от врагов |
| 4       | Нет вражеской армии — Кляксы мелкие и рассеиваются легко; главная опасность — шторм (среда, не бой)      | Комбинация двух котов для управления парусом/линзой под давлением среды |
| 5       | Нет традиционных врагов вообще — Маэстро Улыбка отвлекает, не атакует                                    | Затмение (совместная способность) как решение, не оружие                |
| 6       | Бесконечный марш — не обязателен к уничтожению; финал — защита без боя, пока Элиас слушает                | Все прежние способности применяются для *защиты*, не разрушения        |
| 7       | Единственный настоящий "boss fight" всей игры — Страж Безмолвия, 4 замка, каждая фаза проверяет **пару** уже известных способностей | Комбинаторная проверка полного набора — новых правил не вводится        |

Ключевое наблюдение: явного вражеского combat-encounter почти нет на уровнях 4 и 5 вовсе, а
единственный полноценный "босс-файт" — в самом конце (уровень 7). Кривая сложности этой игры
устроена не как нарастание боевого давления, а как нарастание **комбинаторной/пространственной**
сложности (больше механик приходится сочетать одновременно) при почти неизменном или
понижающемся боевом давлении в середине игры (4-5) перед финальным пиком. Это прямо соответствует
ритму §14 «Ритм уровня» (35% исследование / 25% головоломки / 25% бой / 15% спокойные сцены как
ориентир, не формула — «шестой уровень может уделять больше времени истории», «седьмой —
кульминации»).

**Что это значит для будущей числовой балансировки** (`ABL-001`, Фаза 4, вне scope этой задачи):
здоровье/урон новых врагов должны подбираться так, чтобы бой уровня 1 был самым щадящим
(явно описано в сценарии), а не постепенно расти к уровню 6 — рост сложности искать в количестве
одновременных требований (беги + уклоняйся + используй окружение), а не в цифрах HP.

## GAM-006 — Checkpoint и fail-state rules

Взято из сценария §14 «Сложность и честность» и уже реализовано в коде (`GameSession`,
`src/core/game-session.ts`) — формализуется здесь, а не изобретается заново:

- контрольная точка ставится **перед** сложным испытанием, а не далеко от него (сценарий);
  реализовано как `reachCheckpoint(checkpointId)` + `BondHealth.restore()` при достижении —
  `src/core/game-session.ts:198-203`;
- падение в воду/пропасть возвращает кота на ближайшую безопасную поверхность с небольшим
  штрафом, а не мгновенной смертью (сценарий, уровень 1 §«вода не используется как мгновенная
  смерть»); технически: `restartCheckpoint()` восстанавливает здоровье и врагов, не откатывает
  собранные искры/прогресс уровня — `src/core/game-session.ts:205-214`;
- сюжетные диалоги не нужно пересматривать после поражения (сценарий) — соответствует
  архитектурному требованию плана §8 «respawn не запускает повторно просмотренные диалоги»
  (ещё не проверено тестом для нового канона диалогов, см. `docs/AUDITS/REGRESSION_CHECKLIST.md`);
- поражение не отнимает больше 60–120 секунд прогресса (план §12 «Release playtest gate») —
  не измерялось на новых 7 уровнях (graybox), измерение — часть будущего `QAT-101`/`QAT-201`
  playtest по каждому уровню;
- shield/bond health синхронизированы с HUD (`snapshot.bondHealth`/`maxBondHealth` →
