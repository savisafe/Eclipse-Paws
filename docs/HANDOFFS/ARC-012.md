# ARC-012 — Описать добавление новой ability/enemy/level

- Статус: DONE (принято координатором 2026-09-05)
- Владелец: Claude
- Scope: новый файл `docs/ADDING_CONTENT.md`. Чистая документация, ноль изменений в коде — не
  пересекается ни с чем, включая работу art-агента.
- Изменённые файлы: `docs/ADDING_CONTENT.md` (новый).
- Что реализовано: пошаговые инструкции для трёх сценариев (враг/способность/уровень), основанные
  на реальном чтении текущего кода (не на предположениях):
  - **Враг:** конфиг → регистрация в `createLevelContent`/реестре типов → расстановка в
    `enemies` уровня → бесплатная валидация через `validateCampaignContent` → отдельно нужный шаг
    для визуала (`*_ENEMY_FRAMES` в `adapters/phaser/*-enemy-atlas.ts`, не связан с content-схемой)
    → существующие тесты `campaign-levels.test.ts`.
  - **Способность:** три фиксированных слота на кота (primary/special/support) + ultimate;
    явно предупреждено, что поле `AbilityConfig.effect` **декоративное** — визуал способности
    жёстко захардкожен по `catId` в `platformer-effects.ts`/`combat-ability-system.ts`, а не
    выбирается по `effect`. Указано, где реально считается урон (`core/game-session.ts`,
    `core/combat/combat-rules.ts`), а не в content.
  - **Уровень:** `CampaignLevelDefinition` → `CAMPAIGN_LEVEL_ORDER` → диалоги (опционально) →
    враги → фон (координация с art-агентом) → **ручное условие по `level.index`** в
    `prototype-scene.ts` для выбора enemy-атласа (не декларативно) → валидация → тесты.
  - Definition of Ready/Done чек-лист, привязанный к существующим npm-скриптам.
  - Отдельный раздел «Известные ограничения» с находками, которые не были очевидны до чтения
    кода: `effect` не используется нигде для выбора визуала; `LEVEL_MONSTER_ROSTERS` экспортируется,
    но нигде не потребляется (мёртвый код/задел на будущее); порядок уровней **продублирован** в
    двух местах (`CAMPAIGN_LEVEL_ORDER` и приватный массив внутри
    `ProgressService#nextLevel()`) — рассинхронизация не ловится ни линтом, ни
    `validateCampaignContent`; выбор enemy-атласа в `prototype-scene.ts` сделан условными ветками
    по `level.index`, а не декларативно.

    заключалась в документировании текущего процесса, а не в его улучшении. Каждое найденное

  - Не описывал сюжетное/художественное наполнение (что именно добавлять по новому сценарию) —
    документ описывает механику добавления, контент-нейтрален по отношению к смене канона.
