# COM-010A — Data-driven slideshow engine для пролога и эпилога

- Статус: REVIEW
- Владелец: Claude
- Scope: `src/ui/components/Slideshow.tsx` (новый), `src/content/story/*` (новое),
  `src/core/state-machine/app-state.ts`, `src/application/services/app-controller.ts`,
  `src/ui/App.tsx`, `src/ui/styles/game.css`, тесты. Не пересекается с файлами art-агента.

## Что реализовано

- **`Slideshow.tsx`** — единый переиспользуемый компонент (`COM-010A`), ничего не знает про
  пролог/эпилог конкретно: принимает `panels: SlidePanel[]`, `onComplete`, опциональный
  `autoAdvanceMs`. Поддерживает: клик/`Далее`/`Продолжить` (на последней панели) для ручного
  перехода, чекбокс «Автопрокрутка» (COM-015), кнопку «Пропустить» (мгновенно завершает), клавиши
  `Space`/`ArrowRight`/`Enter` для перехода и `Escape` для пропуска, субтитры показаны всегда по
  умолчанию (план §14 «Доступность»), счётчик `N / total`.
- **`src/content/story/{slide-panel,prologue-panels,epilogue-panels}.ts`** — данные: 8+8 панелей,
  подписи — **дословные** цитаты рассказчика/персонажей из `ECLIPSE_PAWS_SCENARIO.md` (пролог §10,
  эпилог), ничего не придумано; две панели (пролог #5 «Коллапс», эпилог #5 и #7) намеренно без
  подписи — сценарий явно говорит «текст отсутствует»/описывает их только визуально.
- **`AppState`/`APP_TRANSITIONS`** (`core/state-machine/app-state.ts`) — добавлены состояния
  `prologue` (`main-menu → prologue → loading-level`) и `epilogue`
  (`level-result → epilogue → credits`), с возможностью вернуться в `main-menu` из обоих (защитный
  путь, не основной сценарий).
- **`AppController`** — новые методы `showPrologue()`, `prologueFinished()`, `showEpilogue()`;
  `showCredits()` расширен принимать переход и из `epilogue`, не только из `level-result`.
- **`App.tsx`**:
  - «Новая игра» теперь **всегда** показывает пролог первым (`startBrandNewGame`, план §13
    master regression checklist: «новая игра запускает пролог»), затем **бесшовно** переходит в
    геймплей уровня 1 (`handlePrologueComplete` создаёт `GameplayController` и вызывает
    `prologueFinished()`) — **без** промежуточной карточки `StoryIntro`, ровно как того требует
    COM-019 («panel 8 → gameplay») и master checklist («skip ведёт в уровень 1 без двойной
    загрузки»). `StoryIntro` при этом не удалён — он остаётся для выбора уровня/перехода между
    уровнями/«Продолжить», где это осмысленный рекап, а не для самого первого входа.
  - Финал (уровень «Сердце вечного сна», кнопка «Далее: Финал») теперь ведёт в эпилог
    (`startEpilogue`), после которого (`handleEpilogueComplete`) — в уже существующий экран
    `Credits`, без изменений в самом `Credits.tsx`.
  - Debug-launch (`?level=`/`?checkpoint=`) по-прежнему полностью обходит пролог (вызывает
    `startNewGame()` напрямую, как и раньше) — это осознанно, debug-режим существует именно для
    того, чтобы не проходить пролог каждый раз.

## Что намеренно не реализовано

- **`COM-011`..`COM-014`** (layout со temp-артом, проверка на детскую понятность, финальные
  панели, parallax/анимация) — не требуются: панели уже финальные (`docs/COMIC_STORYBOARD.md`),
  parallax/анимация — отдельная художественная доработка поверх уже работающего движка.
- **`COM-016`** (audio controls) — движок не проигрывает и не управляет звуком; в сценарии у
  панелей нет обязательной озвучки текста, только фоновая музыка (не в scope этой задачи).
- **`COM-017`/`COM-018`** (сохранение факта просмотра в progression, повторный просмотр в
  «Воспоминаниях») — **сознательно не реализовано**. Это потребовало бы менять схему `SaveGame`
  (миграция версии) ради экрана «Воспоминания», которого не существует вообще — половинчатая
  фича без потребителя. Пролог/эпилог сейчас смотрятся каждый раз при «Новая игра»/полном
  прохождении — это уже соответствует буквальному требованию сценария и master checklist, но не
  полному COM-017/018.
- **`COM-101`/`COM-101A`** (эпилог как отдельная задача) — фактически уже выполнены тем же кодом
  (один движок на оба, как и требует `COM-101A`: «без отдельной реализации»).
- Debug-параметр для прямого запуска пролога/эпилога в изоляции (например `?slide=prologue`) — не
  добавлялся, не запрашивался; при необходимости — простое расширение `debug-launch.ts` отдельной
  задачей.
- Автопрокрутка выключена по умолчанию (пользователь должен явно включить чекбокс) — это
  осознанный выбор в пользу ручного контроля по умолчанию (план §14: «управление... удержание
  кнопки заменить переключателем», предпочтение явному действию игрока), а не обязательное
  автовоспроизведение сразу.

## Изменённые контракты

- `AppState` — расширен двумя новыми значениями (`prologue`, `epilogue`). Любой код, делающий
  исчерпывающий `switch`/сравнение по всем значениям `AppState` вне `App.tsx`, должен быть
  проверен — на момент задачи такого кода, кроме `App.tsx`, не найдено (`APP_TRANSITIONS` — единый
  источник переходов, использован).
- `AppController.showCredits()` — расширено принимаемое исходное состояние (`level-result` **или**
  `epilogue`), обратная совместимость сохранена (не убирает старый путь).
- Новый публичный экспорт из `@content/index`: `SlidePanel`, `PROLOGUE_PANELS`, `EPILOGUE_PANELS`.

## Ручная проверка

Не выполнена в браузере вручную (тот же известный блокер с диалогом подтверждения на машине
пользователя при `npm run dev`/`preview_start`). Вместо этого — полный e2e-прогон реальным headless
Chromium, кликающим по настоящему DOM через настоящий dev-сервер (Playwright поднимает его сам).

## Известные ограничения

- Прогресс-бар `N / total` — только текст, не визуальный индикатор (точки/полоса) — минимальный
  вариант, легко заменить визуальным компонентом из UI-кита (`assets/ui/*`) отдельной задачей.
- Подписи к панелям без готового текста (пролог #5, эпилог #5/#7) показываются как отсутствие
  `<p>` вовсе — работает, но стоит решить в будущем, нужен ли для этих панелей хотя бы
  screen-reader-only текст описания изображения (сейчас `alt=""` у `<img>`, намеренно decorative,
  так как подпись уже даёт контекст, где она есть; для панелей без подписи изображение полностью
  без текстового описания — accessibility-пробел, стоит адресовать в ACC-задачах Фазы 12).

## Риски для следующих задач

- Любая будущая работа над `SaveGame`-схемой (`COM-017`/`COM-018`) должна учитывать, что пролог
  сейчас проигрывается **каждый раз** при «Новая игра» — если добавится «просмотрено один раз»
  логика, нужно явно решить, должна ли она пропускать пролог автоматически или только предлагать
  это как настройку (сценарий не требует пропуска по умолчанию).
- `App.tsx` продолжает расти (много `useCallback`) — не рефакторил структуру компонента, вне scope
  этой задачи.
