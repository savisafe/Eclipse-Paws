# ARC-015 — Добавить debug launcher любой главы, зоны и checkpoint

- Статус: DONE (принято координатором 2026-09-05, подтверждено e2e-прогоном)
- Владелец: Claude
- Scope: `src/ui/debug-launch.ts` (новый), `src/ui/App.tsx`, `src/ui/components/GameCanvas.tsx`,
  `README.md`. Не пересекается с файлами art-агента.
- Контекст: до этой задачи уже существовал частичный, необорганизованный debug-launcher —
  разрозненные вызовы `new URLSearchParams(window.location.search)` в трёх местах (`App.tsx` × 3
  функции, `GameCanvas.tsx` × 1 место), поддерживающие `?level`, `?heroLevel`,
  `?phaseDurationMs`, `?startNearCombat`, `?startNearFinish` — но без единой точки и без
  поддержки checkpoint.
- Изменённые файлы:
  - `src/ui/debug-launch.ts` (новый) — `readDebugLaunchParams()` (единый парсинг всех dev-флагов,
    с валидацией: `level` проверяется против `CAMPAIGN_LEVEL_ORDER`, `heroLevel`/`phaseDurationMs`
    отклоняют некорректные числа) и `shouldAutoStartDebugLaunch()`.
  - `src/ui/App.tsx` — три отдельные функции парсинга URL (`initialLevelFromLocation`,
    `devHeroLevelOverride`, инлайновый парсинг `phaseDurationMs`) заменены на один вызов
    `readDebugLaunchParams()` (вычисляется один раз на уровне модуля). Добавлена поддержка
    `?checkpoint=<id>` — `createCampaignGameplay` после создания `GameplayController` вызывает уже
    существующий публичный метод `gameplay.reachCheckpoint(id)`, если `id` найден среди
    `CAMPAIGN_LEVELS[levelId].checkpoints` (иначе игнорируется, а не падает на несуществующий
    уровня чекпоинт). Добавлен новый эффект: при запросе `?level`/`?checkpoint` и достижении
    `appState === 'main-menu'` автоматически вызывается `startNewGame()` — пропускает
    MainMenu/StoryIntro для этих двух флагов.
  - `src/ui/components/GameCanvas.tsx` — дублирующийся парсинг `startNearFinish`/`startNearCombat`
    заменён на `readDebugLaunchParams()`.
  - `README.md` — задокументирован полный список debug query-параметров (см. также `AUD-003`).
- Что реализовано: единая точка входа для всех dev-only query-параметров + новая возможность
  (`checkpoint`) + автостарт для `level`/`checkpoint`.
- **Регрессия, найденная и исправленная в этой же сессии:** первая версия делала автостарт при
  наличии **любого** debug-флага, включая `heroLevel`/`phaseDurationMs`/`startNearCombat`/
  `startNearFinish`. Прогон `npm run test:e2e` (специально запущен для проверки, а не только
  `npm run test`) показал 8 упавших тестов в `tests/e2e/boot-menu.spec.ts` — все тесты, которые
  используют `?phaseDurationMs=`/`?startNearFinish=`/`?startNearCombat=` вместе с ручным кликом
  по «Новая игра» → «Начать уровень» (существующий, устоявшийся в проекте паттерн), падали с
  таймаутом ожидания кнопки «Новая игра», потому что автостарт уже пропускал меню до клика.
  Исправлено: `shouldAutoStartDebugLaunch()` теперь проверяет **только** `level`/`checkpointId` —
  флаги-модификаторы (`heroLevel`/`phaseDurationMs`/`startNearCombat`/`startNearFinish`)
  по-прежнему требуют ручного старта, как и было в исходном (до этой задачи) поведении. После
  исправления `npm run test:e2e` перепрогнан и все тесты снова проходят (см. «Проверки»).
- Что намеренно не реализовано:
  - Не добавлял отдельный debug UI-экран (список уровней/чекпоинтов кнопками) — план явно
    говорит "debug launcher", а не "debug UI"; URL-параметры — уже установившийся в проекте
    паттерн, расширение этого паттерна дешевле и достаточно.
  - Не исправлял хардкод `#checkpointId = 'garden-gate'` в `GameSession` (единый дефолт для всех
    уровней вместо чтения первого чекпоинта конкретного уровня) — обнаружено при исследовании
    (см. `docs/AUDITS/KNOWN_ISSUES.md` #5), но исправление не требовалось для работы
    `?checkpoint`, так как `PrototypeScene` уже подстраховывается через
    `?? this.#level.checkpoints[0]` при несовпадении id.
- Изменённые контракты: нет изменений публичного API — `GameplayController.reachCheckpoint`
  использован как есть, ничего не добавлено в `@core`/`@application`. Новый экспорт
  `@ui/debug-launch` — внутренний UI-модуль, не пересекает границу `ui`↔`application`/`core`.
- Проверки и результаты:
  - `npm run lint` — чисто (после исправления одной находки: `react-hooks/set-state-in-effect`
    заблокировал прямой синхронный вызов `startNewGame()` внутри эффекта — обёрнуто в
    `window.setTimeout(fn, 0)` с cleanup, по аналогии с уже существующим boot-эффектом).
  - `npm run typecheck` — чисто.
  - `npm run test` — 16 файлов / 63 теста (было 15/45 до задачи; добавлено 9 на
    `debug-launch.ts`, включая явный regression guard `shouldAutoStartDebugLaunch` для
    `heroLevel`/`phaseDurationMs`/`startNear*` + 1 интеграционный тест в `app.test.tsx` через
    `vi.resetModules()`/динамический импорт, проверяющий полный путь `?level=&heroLevel=` →
    пропуск меню → экран загрузки нужного уровня).
  - `npm run test:e2e` — **прогнан дважды**: первый прогон поймал регрессию (8 failed), второй
    (после исправления) — все тесты снова зелёные. Это первый раз в сессии, когда e2e реально
    запускался (а не только читался как существующий) — ценно тем, что он единственный ловит
    подобные интеграционные регрессии, которые unit-тесты по своей природе не видят (мокают
    `GameCanvas`).
  - `npm run build` — production build проходит.
  - `npm run format:check` — чисто.
- Ручная проверка: не выполнена в браузере вручную (dev-сервер через `preview_start` завис за
  локальным диалогом подтверждения на машине пользователя — тот же известный блокер, что и в
  `ARC-011`), но `npm run test:e2e` — это реальный headless Chromium, кликающий по настоящему DOM
  через настоящий dev-сервер (Playwright поднимает его сам, минуя блокирующий helper) — это
  сильнее, чем просто unit-тесты, и является практическим эквивалентом ручной проверки для этой
  задачи.
- Скриншоты/видео: не применимо.
- Известные ограничения:
  - `?checkpoint` молча игнорирует несуществующий для уровня id, без предупреждения в консоли —
    при опечатке в URL это можно не заметить сразу.
  - Автостарт для `level`/`checkpoint` пропускает `StoryIntro` (карточку с сюжетом/названием
    уровня) — это осознанно (иначе пришлось бы всё равно кликать «Начать уровень», сводя на нет
    смысл «launcher»), но если понадобится debug-режим, показывающий intro перед стартом, это
    отдельная (не запрошенная) вариация.
- Риски для следующих задач: нет прямых рисков для `ARC-010`/продолжения `ARC-011` — модуль

  **обязательно** гонять `npm run test:e2e`, а не только `npm run test`, при любом изменении
