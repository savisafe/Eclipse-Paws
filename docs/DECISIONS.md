# Технические решения

## ADR-001 — Layered core без framework-зависимостей

- Статус: принято
- Дата: 2026-09-01

Core и application остаются pure TypeScript. Phaser и React — внешние адаптеры. Это позволяет
тестировать механику без браузера и в будущем добавить Capacitor, не переписывая правила.

## ADR-002 — Vite 8 и совместимый React plugin

- Статус: принято
- Дата: 2026-09-01

Используются актуальные стабильные Vite 8 и `@vitejs/plugin-react` 6. Первоначально проверенная
версия плагина 5 не принимала Vite 8 по peer dependency; зависимости обновлены до совместимой
пары без `--force`/`--legacy-peer-deps`.

## ADR-003 — Phaser остаётся на major 3

- Статус: принято
- Дата: 2026-09-01

Хотя npm помечает Phaser 4 как latest, техническое задание требует Phaser 3. Зафиксирована
последняя доступная версия ветки 3 (`3.90.0`), чтобы сохранить ожидаемые API и снизить риск
архитектурного дрейфа.

## ADR-004 — CSS placeholder art на этапе 0

- Статус: принято
- Дата: 2026-09-01

Boot и главное меню используют локальные CSS-формы без внешних изображений, шрифтов или CDN.
Это даёт единый временный стиль, нулевой лицензионный риск и не связывает будущие спрайты с UI.

## ADR-005 — Zustand только для UI/session

- Статус: принято
- Дата: 2026-09-01

Zustand хранит отображаемое состояние приложения и временные настройки UI. Доменные state
machines и будущий gameplay state остаются вне React. Persist намеренно не подключён: доступ к
localStorage будет реализован только через `SaveRepository` на этапе сохранений.

## ADR-006 — Phaser загружается отдельным lazy chunk

- Статус: принято
- Дата: 2026-09-01

Главное меню не загружает игровой движок. Phaser импортируется после выбора «Новая игра» и
собирается в отдельный chunk около 1,2 MB. Порог предупреждения Vite установлен в 1,3 MB именно
для этого известного engine chunk; основной React bundle остаётся около 250 KB.

## ADR-007 — Переход к side-scrolling платформеру

- Статус: принято по прямому запросу пользователя
- Дата: 2026-09-01

Первоначальная top-down формулировка заменена 2D side-scrolling платформером. Core правил фаз,
урона, общей Связи и checkpoint сохранён; заменён Phaser adapter: горизонтальный мир, гравитация,
платформы, прыжки и следящая камера. Управление сменой фазы перенесено со `Space` на `R`, чтобы
`Space` оставался стандартной кнопкой прыжка.

## ADR-008 — Runtime-анимации и concept art

- Статус: принято
- Дата: 2026-09-01

Полнотелые состояния котов и монстров рисуются локально в Phaser, поэтому анимации детерминированы
и не требуют сети. Оригинальный ImageGen concept sheet хранится в `src/assets/concepts` как
визуальный ориентир для последующей нарезки production-спрайтов, но не загружается в runtime bundle.

## ADR-009 — Детализированный растровый atlas с runtime-нормализацией

- Статус: принято по визуальному референсу пользователя
- Дата: 2026-09-01

Программные силуэты заменены оригинальным ImageGen atlas в стиле утверждённого concept sheet.
Генератор сохранил фон-шахматку без настоящего alpha и расположил широкие позы нестрого по сетке.
Phaser adapter поэтому один раз при загрузке удаляет только связанный нейтральный фон, переносит
заданные области в 24 одинаковых кадра 256×256 и освобождает исходную texture. Core, physics bodies
и gameplay rules от растрового формата не зависят.

## ADR-010 — Companion tether вместо жёсткого телепорта

- Статус: принято по результатам playtest
- Дата: 2026-09-02

Неактивный кот следует на дистанции около 82 px. Если расстояние превышает 290 px, вертикальный
разрыв слишком велик или progress отсутствует 720 мс, напарник превращается в фазовую искру,
игнорирует collision и материализуется рядом. При переключении застрявший кот материализуется
немедленно. Это устраняет soft-lock, не превращая пару в одного постоянного персонажа.

Статус изменён 2026-09-02: решение заменено ADR-013 после повторного playtest.

## ADR-011 — Сильнее выраженная фазовая асимметрия

- Статус: принято по результатам playtest
- Дата: 2026-09-02

Модификаторы изменены с 125%/60% на 150%/25%. Оба кота сохраняют базовую атаку, но неправильная
фаза становится явно неэффективной; HUD, tint и интенсивность attack VFX показывают статус без
опоры только на цвет.

## ADR-012 — Painterly raster environment

- Статус: принято по визуальному запросу пользователя
- Дата: 2026-09-02

Плоские геометрические горы и одноцветные платформы заменены локальным ImageGen background и
повторяемой каменно-мшистой texture. Collision остаётся отдельной простой геометрией Phaser;
визуальные ассеты не влияют на правила или позиционирование gameplay objects.

## ADR-013 — Tag-switch: один физический кот

- Статус: принято, заменяет ADR-010
- Дата: 2026-09-02

Одновременно физическое тело имеет только активный кот. `Tab` переносит позицию, velocity context и
camera ownership второму герою через короткую уникальную анимацию света/тьмы. Это полностью
исключает follower soft-lock и визуальное «побледнение» напарника. Общая Связь и фазовая
асимметрия сохраняются.

## ADR-014 — CampaignLevelDefinition для уровней 1–5

- Статус: принято
- Дата: 2026-09-03

Маршрут, фон, platforms, phase platforms, hazards, checkpoints, sparks, enemy spawns, boss и
mechanic задаются одним типизированным level config. Общая Phaser scene принимает definition и
не содержит `switch` по номеру уровня. Лес и библиотека добавлены без изменения combat core API.

## ADR-015 — Три фазы финального босса по health thresholds

- Статус: принято
- Дата: 2026-09-03

Pure `BossPhaseTracker` делит здоровье Пожирателя Зари на интервалы >⅔, >⅓ и ≤⅓. Phaser adapter
отображает текущую фазу; в третьей фазе шкала Затмения регулярно восполняется для совместного
приёма. Переходы тестируются без renderer и не зависят от FPS.

## ADR-016 — PWA без runtime-зависимости

- Статус: принято
- Дата: 2026-09-03

Manifest и небольшой service worker находятся в `public/`, регистрируются только в production и
runtime-cache’ят same-origin assets после первого запуска. Дополнительный PWA framework не нужен.
Исходные painterly PNG сохранены, а runtime использует JPEG quality 84: общий сетевой вес пяти
backgrounds снижен примерно с 15 MB до 4 MB.

## ADR-017 — Ограниченные object pools для частых эффектов

- Статус: принято
- Дата: 2026-09-03

Универсальный `GameObjectPool` имеет два реальных применения: частицы tag-switch и волны ultimate.
Объекты переиспользуются вместо allocate/destroy на каждом эффекте; pool уничтожается вместе со
scene. Остальные редкие эффекты остаются одноразовыми, чтобы не усложнять lifecycle без пользы.
